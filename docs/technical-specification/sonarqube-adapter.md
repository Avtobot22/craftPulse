# Адаптер SonarQube

Бинарник `adapter-sonarqube` читает SonarQube Server или Community Build по HTTPS. Область `analysis_project` задаётся ключом проекта. Сборщику нужен пользовательский токен с правом Browse на проект. В `collect` передаётся JSON с полем `token`. Ключ экземпляра берётся из `id` ответа `/api/system/status`. Если поле пустое, ключом служит нормализованный HTTPS-адрес.

`Probe` проверяет право Browse через `/api/components/show`, затем подтверждает `read_current` чтением анализов и issues. Поиск issues по закрытому проекту может вернуть пустой список с HTTP 200. Для Community Build стенда анализ веток помечен `partial` с причиной `edition_does_not_support_branch_analysis`, анализ MR - с причиной `edition_does_not_support_mr_analysis`. Для редакций без подтверждения в протоколе причина `edition_capability_unverified`. Анализ MR без поддержки редакции даёт `NOT_EVALUATED` для Sonar. Штатные проверки craftPulse выполняются отдельно.

## Проверка доступа

Режим проверки - `user_token`. Через `PutCredentials` с назначением `user_token` передаются `user_id` craftPulse и пользовательский токен SonarQube в поле `secret`. Адаптер подтверждает вход и логин через `/api/users/current`. Если в запросе или сохранённых учётных данных есть идентификатор аккаунта, он должен совпасть с логином.

Адаптер проверяет Browse через `/api/components/show` тем же токеном. Ответ 403 после подтверждения аккаунта даёт `denied`. Ошибка, неподтверждённая личность или превышение общего бюджета в 2 с дают `unknown`. Ответ содержит время проверки и предел свежести 60 с.

До стендовой приёмки успешная проверка Browse возвращает `unknown` с причиной `sonarqube_access_revocation_unverified`.

## Пакет отчётов

Сбор `reports` использует схему пакета `findings`. Анализ передаётся как `report_file/1` вида `sonar`. Ключ проекта задаёт пространство имён, ключ анализа задаёт ID. Время анализа приходит в `finished_at`, ревизия в `sha`, версия сервера в `producer_version`. Файл формата `envelope` содержит состояние списка issues, сами issues и доступные значения метрик `ncloc`, `bugs`, `vulnerabilities`, `code_smells`, `coverage`, `duplicated_lines_density`.

У последнего анализа проекта есть issues и measures. У прежних анализов доступны метаданные. При отсутствии ревизии отчёт получает `missing_revision`. Значение `sha` остаётся пустым, находки для этого анализа не привязываются к коммиту.

Каждый issue в файле содержит исходный ключ, правило с именем, языком и репозиторием, относительный путь, диапазон строк, тип, severity, статус и резолюцию. Текст замечания и фрагменты кода в пакет не входят. При достижении окна поиска в 10 000 issues пакет помечается `partial` с причиной `issue_search_window_exceeded`. Если следующая страница недоступна или состав выдачи меняется между обходами, адаптер возвращает `unavailable` и оставляет курсор на прежней позиции.

`Manifest` перечисляет анализы за полуоткрытый период по паре «время, ключ». У последнего анализа в перечне поле `issue_count` содержит число issues текущего состояния проекта.
