# Автоматизация обновлений зависимостей

Dependabot обнаруживает известные уязвимости и открывает security update PR, когда может подобрать исправляющее обновление. Copilot дополняет этот процесс: разбирает проблему совместимости, исправляет затронутый код и готовит PR с результатами проверок.

## Подготовка агента

Правила проекта находятся в [.github/copilot-instructions.md](../.github/copilot-instructions.md). Сценарий обслуживания зависимостей хранится в [dependency-maintenance.prompt.md](../.github/prompts/dependency-maintenance.prompt.md). Наличие этих файлов само по себе не создаёт и не включает облачную автоматизацию.

Облачные автоматизации настраиваются в [Agents → Automations](https://github.com/Avtobot22/craftPulse/agents/automations). Они принадлежат создавшему их пользователю; запуски используют его квоту Copilot и GitHub Actions. Подписки участников не образуют общий пул. Не создавайте одинаковую автоматизацию от каждого участника.

## Обслуживание зависимостей

Сценарий `Dependency maintenance` запускается событием `Dependabot alert created` и обрабатывает alert из контекста события. Он готовит не более одного draft PR за запуск. Если Dependabot уже открыл подходящий PR с зелёными проверками, дополнительный PR не требуется. Если обновление нарушило совместимость, агент исследует причину и подготавливает исправление. Открытый исправляющий PR предотвращает повторную работу. При отсутствии исправленной версии или входного alert агент завершает сессию без записей в репозиторий и трекер.

Для сценария нужны alert из контекста события, чтение кода, PR и логов CI, выполнение проверок, запись в рабочую ветку и создание draft PR. Область записи для триггера - `Only what this run creates`. Доступ к секретам, изменение настроек, dismiss alerts и слияние PR ему не нужны. Не включайте дополнительные платные лимиты для активации сценария.

Создатель автоматизации включает её после проверки доступности инструментов и расхода квоты. В prompt перенесите содержание файла сценария без YAML frontmatter. Название, триггер и инструменты в интерфейсе определяют фактическое поведение; Markdown служит для ревью и восстановления prompt. `Continuous history` сохраняет контекст прошлых запусков и ставит новые запуски в очередь, чтобы они не перекрывались. Отдельного периодического опроса нет.

## Проверка результата

Перед первым рабочим запуском проверьте, что Dependabot alerts и security updates включены. После запуска откройте сессию и проверьте, смог ли агент получить alerts, не создал ли дубликат и выполнил ли проверки. Отсутствие PR при отсутствии alerts - нормальный результат. Оно не доказывает способность исправить реальную уязвимость.

PR агента проходит тот же обязательный `repository-check`. GitHub может потребовать отдельно разрешить запуск Actions для PR Copilot; это ограничение облачного агента, а не требование чужого одобрения перед merge. Автор принимает решение о готовности изменения и выполняет squash merge.

## Следующие автоматизации

| Автоматизация | Польза | Когда подключать |
| --- | --- | --- |
| Необязательное Copilot code review | Замечания по diff до слияния | Когда хочется дополнительной проверки; не заменяет CI и не требует человеческого approve |
| Точечное исправление CI | Разбор одной упавшей проверки через Fix with Copilot | По реальному падению, без цикла «бот правит → CI падает → бот правит» |
| Триаж Issues | Метки направления, поиск дубликатов и недостающих критериев | Когда задач становится достаточно, чтобы ручной разбор мешал работе |
| Preview на каждый PR | Проверка интерфейса по отдельной ссылке | После появления запускаемого web-приложения и выбора хостинга |
| Обновление документации по изменению API | Выявление расхождения контракта и реализации | После появления кода и проверяемых схем; без автоматического изменения продуктовых требований |

Генерация релизных заметок, группировка Dependabot PR и автоматическое движение карточек уже решаются обычными средствами GitHub. Для них отдельная агентная сессия не требуется.
