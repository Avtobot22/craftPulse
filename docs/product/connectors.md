# Коннекторы

craftPulse получает данные из четырёх типов систем: Git-хостинга, трекера задач, CI и анализаторов кода. Ниже порядок подключения. Он построен по тому, что реально используют российские команды (State of DevOps Russia 2025, более 3 300 респондентов), и по тому, что требовали собеседники в интервью. Подробности по API и ценам платформ - в [исследовании платформ](../research/market/platforms-and-connectors.md).

## Первый выпуск

| Система | Тип | Почему первой |
|---|---|---|
| GitLab self-managed (CE/EE) | Git + CI | GitLab CE на своих серверах у 47,2% команд, GitLab CI у 64,5%. В бесплатной версии нет аналитики разработки: это главная дыра, которую закрывает craftPulse |
| Jira Server / Data Center | Трекер | 35,1% команд работают на своих серверах Jira и YouTrack, и доля растёт. Вендор ушёл из РФ, новых отчётов и плагинов клиенты не получат |
| Яндекс Трекер | Трекер | Лидер российских облачных трекеров, интегрирован с SourceCraft, GitHub и GitLab |
| SourceCraft | Git + CI + AppSec | Платформа, на которой команда собрала прототип: сборщик истории и импорт AppSec уже написаны |
| Отчёты CI: JUnit, покрытие, SARIF | Тесты и анализаторы | Стандартные форматы покрывают большинство тестовых фреймворков и анализаторов. Об этом прямо просили Денис энес и Никита Ненашев |

## Как подключаем

У craftPulse два пути получения данных. Первый - чтение через API и вебхуки Git-хостинга и трекера. Второй - шаг в CI клиента.

Шаг в CI ничего не анализирует заново. Он забирает отчёты, которые pipeline клиента уже создал, и отправляет их в craftPulse:

| Что | Форматы |
|---|---|
| Линтеры | ESLint JSON, golangci-lint checkstyle, Ruff JSON, Checkstyle XML, GitLab Code Quality |
| Анализаторы кода и безопасности | SARIF (SonarQube, Semgrep, CodeScoring, PVS-Studio, Solar appScreener и др.), GitLab SAST/Dependency Scanning |
| Тесты | JUnit XML |
| Покрытие | Cobertura, lcov, JaCoCo |
| Сведения о запуске | Коммит, ветка, MR, длительность и статус jobs, перезапуски |

Так клиент получает результаты своих инструментов с теми правилами и настройками, которые команда уже приняла, а craftPulse не тратит ресурсы на повторный прогон. Собственный базовый анализ craftPulse включается только там, где своих отчётов у клиента нет.

Этот путь работает с любым CI (GitLab CI, Jenkins, GitHub Actions, TeamCity, SourceCraft CI) и не зависит от зрелости API платформы. Это важно для российских платформ: у SourceCraft API версии 0.0.1, и часть методов для CI отозвана.

Для компаний, которые держат код на своих серверах, craftPulse ставится в их контур или подключается через агента внутри периметра.
