# Видение craftPulse

craftPulse - B2B-платформа аналитики разработки. Она собирает данные из Git-хостинга, трекера задач, CI и анализаторов кода, связывает их между собой и показывает каждой роли свой срез: руководителю - выпуск и предсказуемость команд, проектному менеджеру - прогресс проекта, техлиду - риски в коде, разработчику - сигнал в его MR. Каждое число раскрывается до задач, MR, запусков CI и находок, из которых оно получено.

Основной сегмент - компании с 10-100 инженерами без своей аналитической платформы. Крупным компаниям craftPulse ставится в их контур и работает поверх внутренних инструментов через CI и API.

## Основной путь

Создать организацию → описать направления, команды и проекты → подключить Git, трекер и CI → получить дашборды по своей роли → перейти от числа к причинам → получать тот же сигнал в MR.

Руководителю не нужно ходить в CI: результаты проверок видны в craftPulse. Разработчику и техлиду не нужно ходить в craftPulse: оценка и причины приходят в MR.

## Уровни и роли

Иерархия: организация → направление → команда → проект и репозиторий → задача, MR, запуск CI, находка. Один проект может обслуживать несколько команд; правила агрегации заданы явно, чтобы один релиз не считался дважды.

| Роль | С чего начинает | Куда переходит |
|---|---|---|
| CTO, руководство | Выпуск по портфелю, риски, прогресс инициатив | Направление, продукт, проблемная команда |
| Руководитель разработки | Динамика команд: поток, качество, предсказуемость | Команда, период, причины отклонения |
| Проектный менеджер | Прогресс проекта, спринта и эпиков | Задача, связанный MR, упавшая проверка |
| Техлид | Код, безопасность, горячие точки, нестабильные проверки | Файл, правило, история, исключение |
| Разработчик | Свой MR: что нашли и что делать | Строка кода, исходный отчёт анализатора |

Роль определяет, что человек может делать, а область доступа - какие данные он видит. Выбор дашборда не даёт новых прав. Метрики процесса считаются по командам и проектам и не превращаются в рейтинг сотрудников.

## Что внутри

- [Метрики](metrics.md): управленческий и технический слой, формулы, состояния полноты данных.
- [Коннекторы](connectors.md): какие системы подключаем и в каком порядке.
- [Функции](../requirements/features.md): что нужно каждой роли, с приоритетами из интервью.

craftPulse не запускает тесты, линтеры и сканеры клиента сам. Шаг в CI забирает отчёты, которые pipeline уже создал: линтеры, SARIF анализаторов, JUnit, покрытие. Собственный базовый анализ кода (сложность, дублирование, горячие точки, концентрация знаний) используется там, где у клиента таких отчётов нет.

## Архитектура

Стек прототипа: Go на сервере, React и TypeScript в интерфейсе, PostgreSQL для хранения. Приложение модульное: HTTP API и отдельный worker для долгого импорта и расчётов, общие доменные сценарии.

| Слой | Что делает |
|---|---|
| Домен | Иерархия, события, метрики, профили, снимки, правила сопоставимости |
| Сценарии | Подключения, импорт, отчёты, выдача в CI, права, удаление данных |
| Адаптеры | Git, трекеры, CI, анализаторы, внутренние сервисы клиента |
| Инфраструктура | PostgreSQL, очередь задач на PostgreSQL, секреты, мониторинг |

Модули: доступ и права, организации, проекты, коннекторы, импорт, аналитика задач, скоринг, отчёты, выдача в CI, профили. Отдельные микросервисы и базы на модуль не нужны.

## Развитие

После первого выпуска расширяется набор коннекторов и форматов анализаторов, появляются профили корпоративных правил: соглашения о коде, workflow, критерии готовности. Для крупных компаний - установка в контуре, SSO и API.

Дальнее направление - модели, обученные на разрешённых данных компании: её соглашениях о коде и истории решений. Сначала соглашения подаются в контекст модели (RAG), дообучение - отдельный этап с разметкой и оценкой качества. Модель объясняет находки, но не считает итоговые числа и не принимает решения о доступе.
