# Наблюдаемость профиля D

После [запуска профиля D](../README.md) открой Grafana по адресу `http://127.0.0.1:13000`. Пользователь новой установки - `admin`, пароль берётся из файла `grafana-password` каталога секретов. На удалённом стенде пробрось Grafana и VictoriaLogs через SSH.

```sh
ssh -N -L 13000:127.0.0.1:13000 -L 19428:127.0.0.1:19428 defects
```

В разделе **Dashboards** открой **craftPulse · Наблюдаемость**. Дашборд показывает доступность сбора, RED по операциям API, очереди River, память и CPU контейнеров, неудачные входы и отказы в доступе. Правила находятся в **Alerting → Alert rules → craftPulse**. Источник данных, дашборд и правила оповещения загружаются из файлов Compose. Состояние алертов видно в Grafana. Для отправки уведомлений оператору настрой контакт и политику в Grafana.

Профиль использует Grafana 12.4 с отдельным томом `grafana-v12`. При обновлении профиля с Grafana 13 прежний том `grafana` сохраняется. Если на старом стенде вручную добавляли дашборды или контакты, перенеси их через экспорт и импорт. Данные VictoriaMetrics и VictoriaLogs остаются в своих томах.

## Источники и хранение

- VictoriaMetrics опрашивает внутренние `api:9090/metrics`, `worker:9090/metrics` и `cadvisor:8080/metrics` каждые 30 секунд. Данные хранятся 13 месяцев в томе `metrics`.
- VictoriaMetrics находит запущенные `adapter-jiracloud:9090` и `adapter-gitlab:9090` через DNS Compose. На этом порту адаптер публикует срок загруженного сертификата даже после его истечения.
- Worker раз в 15 секунд или реже читает состояние очередей `interactive` и `bulk` из таблицы River. Глубина включает задания со статусом `available`, время запуска которых уже наступило. Возраст считается от `scheduled_at`. Для пустой очереди глубина и возраст равны нулю. При сбое SQL дашборд показывает `River SQL = 0`, а ряды очередей пропадают до следующего удачного запроса.
- cAdvisor читает cgroup v2 в пространстве имён хоста. Docker и containerd нужны ему для сопоставления cgroups с контейнерами. Укажи `CONTAINERD_SOCKET`, если сокет хоста лежит по другому пути. У cAdvisor нет опубликованного порта. VictoriaMetrics сохраняет только ряды CPU и памяти текущего Compose-проекта. Сокеты Docker и containerd дают доступ к API рантайма даже при монтировании с `ro`. На хосте их получает только cAdvisor.
- Память показана как рабочий набор относительно лимита cgroup. Для CPU дашборд делит использованные ядра на квоту контейнера. `CONTAINER_CPUS` задаёт квоту в vCPU для сервисов без отдельного лимита. Worker сохраняет собственную квоту 2 vCPU. Одноразовый `migrate` виден, если cAdvisor успел снять образец до завершения контейнера.
- Docker отправляет stdout и stderr ядра и nginx напрямую в VictoriaLogs по syslog RFC 5424 через UDP-порт хоста `127.0.0.1:19514`. Дополнительный агент для логов не нужен. Драйвер работает в неблокирующем режиме. Когда приёмник недоступен или буфер заполнен, часть сообщений может потеряться. VictoriaLogs хранит сообщения 30 дней в томе `logs`.

Лимиты VictoriaMetrics и VictoriaLogs составляют по 128 MiB, Grafana - 160 MiB. Сравни рабочий набор с лимитом в `docker stats --no-stream`. На Linux проверь пиковую память и счётчик событий OOM в `memory.peak` и `memory.events` cgroup соответствующего контейнера.

## Найти ошибку по correlation ID

Открой интерфейс VictoriaLogs по `http://127.0.0.1:19428/select/vmui/` или отправь запрос через `curl`. Ограничь диапазон временем события. `unpack_json` раскрывает поля JSON из сообщения syslog.

```sh
curl -fsSG http://127.0.0.1:19428/select/logsql/query \
  --data-urlencode 'query=_time:1h "<correlation_id>" | unpack_json | filter correlation_id:="<correlation_id>" | fields _time, service, organization_id, operation_id, reason_code, correlation_id, message'
```

По организации и операции используй следующий LogsQL. Идентификатор организации берётся из аутентифицированного субъекта.

```text
_time:1h | unpack_json | filter organization_id:="<organization_id>" operation_id:="getTeamReport"
```

## Проверка на тестовом стенде

В дашборде **craftPulse · Сбор данных** видны время с последнего успешного сбора,
отставание от watermark, ошибки сбора и прав, отклонения пакетов и срок
сертификатов адаптеров. Правила проверяются каждые 30 секунд.

| Алерт | Условие |
| --- | --- |
| Свежесть сбора | Прошло больше 26 ч с последнего удачного сбора данного вида данных подключения |
| 401/403 | Ошибка класса `auth` за 5 минут, без ожидания |
| Остальные ошибки сбора | Число ошибок одного класса за последние 5 минут растёт в течение часа, в том числе для `adapter_unavailable` |
| Проверка прав | Счётчик ошибок подключения растёт в скользящем окне 2 минуты в течение 5 минут |
| Доля отклонений | Рост более чем на 20 п.п. между соседними окнами по 5 минут, если в текущем окне завершена обработка как минимум пяти пакетов канала и есть данные предыдущего окна |
| Сертификат | До истечения сертификата адаптера меньше 30 дней |

Сценарии с тестовым подключением, сертификатом и откатом описаны в
[приёмке Jira Cloud](../jira-cloud.md#приёмка-выпуска) и [приёмке GitLab](../gitlab.md#приёмка-выпуска).

1. Запусти профиль с пустыми томами. Открой дашборд. Через 1-2 минуты проверь, что в Grafana видны API, worker, cAdvisor, обе очереди и работающие контейнеры проекта. Сделай несколько запросов API, чтобы появились ряды RED.
2. Под обычным пользователем запроси отчёт команды, к которой у него нет доступа. Возьми `correlation_id` из ответа `404` и найди запись в VictoriaLogs. Сверь `organization_id`, `operation_id=getTeamReport`, время и `reason_code=not_found`.
3. Повтори запрос к недоступной команде из той же сессии после первого сбора счётчика. Правило срабатывает, когда число отказов субъекта за 5 минут выросло минимум на 5 относительно предыдущих 5 минут. Выполни серию хотя бы из 10 запросов.
4. Для тестового провайдера сначала получи исход входа и дождись сбора счётчика. Выполни серию входов, в которых провайдер возвращает `error=access_denied` с действительным `state`. Правило срабатывает при росте доли ошибок более чем на 20 процентных пунктов относительно предыдущих 5 минут и минимум пяти исходах за текущие 5 минут. Для нового провайдера без предыдущих событий базовая доля равна нулю.
5. Создай отдельный контейнер с большим лимитом и занятым tmpfs. Снизь лимит до 64 MiB, чтобы рабочий набор превысил 90%. Подставь имя Compose-проекта в метку, если запускал его с `-p`.

```sh
docker run -d --name cp-memory-probe --cpus 0.5 --memory 96m --memory-swap 96m \
  --label com.docker.compose.project=craftpulse-profile-d \
  --label com.docker.compose.service=memory-probe \
  --tmpfs /probe:size=64m alpine:3.23 \
  sh -c 'dd if=/dev/zero of=/probe/data bs=1M count=59 && sleep 600'
docker update --memory 64m --memory-swap 64m cp-memory-probe
```

Дождись `Firing` для неудачных входов, отказов субъекта и памяти `cp-memory-probe`. Интервал вычисления правил - 30 секунд. Сохрани снимки дашборда и алертов, затем удали тестовый контейнер командой `docker rm -f cp-memory-probe`.

Остальные правила срабатывают при p95 выше 2 секунд в течение 10 минут, возрасте старейшего задания `interactive` выше 2 минут или `bulk` выше часа, а также при любом задании в состоянии `discarded`. Алерт по `discarded` остаётся активным, пока эта запись хранится в River.
