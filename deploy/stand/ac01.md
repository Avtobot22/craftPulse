# AC-01. Вход, завершение сессии и изоляция организаций

## Настройка стенда

Используй выделенный стенд с тестовым GitLab из [#87](https://github.com/Avtobot22/craftPulse/issues/87).
[Параметры выката](../profile-d/rollout.example.json) задают issuer
`https://gitlab.defects.team` для обеих организаций:

| Slug | Приложение GitLab | Первый администратор |
| --- | --- | --- |
| `org-a` | `craftpulse-org-a` | `cp87-admin-a` |
| `org-b` | `craftpulse-org-b` | `cp87-admin-b` |

В комплекте восстановления `gitlab-secrets.sops.json` журнал GitLab находится
в поле `provisioning`. В `deploy/profile-d/rollout.json` на сервере подставь
идентификаторы приложений из `objects.<приложение>.application_id` и
идентификаторы администраторов из `objects.<учётная запись>.id` в качестве
OIDC `sub`. После восстановления GitLab сверь эти значения с действующими
приложениями и учётными записями.
Для каждого приложения callback должен быть
`https://craftpulse.defects.team/o/<slug>/callback`, scopes - `openid profile`.

Через `sops edit` заполни `oidc_client_secrets` в комплекте установки SOPS + age.
Для ключа `org-a` используй `credentials.craftpulse-org-a.secret` из журнала GitLab,
для `org-b` - `credentials.craftpulse-org-b.secret`. Сохрани настройки и ключи
действующей установки и используй отдельный комплект оператора вне checkout.
Для профиля D выполни [команду выката](../profile-d/README.md#выкат):

```sh
python3 deploy/profile-d/rollout.py deploy --bundle /secure/stand.sops.json "$RELEASE_SHA"
```

После успешного `api install` сохрани закрытый снимок начальной базы этой
установки до входа администраторов. Для AC-01 нужны пустые организации,
в том числе `org-b` в статусе `setup`. Для существующих организаций
`api install` сохраняет статус, OIDC-регистрацию и первого администратора.
Если эти параметры отличаются от журнала, используй чистую базу выделенной
установки.

Для [установки через Compose](README.md) те же идентификаторы задай в
`.env` приложения. Смонтируй секреты OIDC из шифрованного комплекта
в пути, указанные в [product.compose.yaml](product.compose.yaml).

## Два прогона

На машине оператора нужны Python 3.9+, SOPS, ключ age к зашифрованному
журналу GitLab или комплекту восстановления и доступ к HTTPS приложения и GitLab.
Если используется внутренний CA, передай путь к
его цепочке через `--ca`. Автопроверка расшифровывает журнал в памяти и входит
через формы GitLab. Она создаёт по одной команде и проекту в каждой организации,
а пользователю `cp87-member` назначает роль `dev_lead` в команде `org-a`.
Структуры с посторонними данными и роли тестового пользователя с другой
областью требуют отдельного стенда с исходным снимком.

Выполни первый прогон:

```sh
python3 deploy/stand/ac01.py --gitlab-bundle /secure/gitlab.sops.json \
  --sha "$RELEASE_SHA" --report /secure/ac01-run-1.json
```

Между прогонами останови API и worker выделенной установки, восстанови исходный
снимок базы и запусти тот же выпуск. В первом прогоне вход администратора активирует `org-b`, поэтому
проверка отказа в ещё не настроенной организации требует исходного состояния.
Сохрани второй прогон в новый файл и сравни результаты операций craftPulse.
Число запросов к GitLab может отличаться, если GitLab сохранил согласие на вход:

```sh
python3 deploy/stand/ac01.py --gitlab-bundle /secure/gitlab.sops.json \
  --sha "$RELEASE_SHA" --report /secure/ac01-run-2.json

jq -e -s 'all(.[]; .outcome == "passed") and
  (map(del(.started_at, .finished_at) |
    .requests |= map(select(.operation != "gitlabSignIn" and .operation != "gitlabAuthorize"))) |
    .[0] == .[1])' \
  /secure/ac01-run-1.json /secure/ac01-run-2.json
```

Запись содержит SHA из `/version`, время, операции и проверенные поля ответов.
Перед записью команда ищет в JSON наблюдавшиеся значения паролей, OIDC-секретов,
cookie, кодов авторизации и CSRF-токенов. Сохрани обе записи с артефактами выпуска.

После второго прогона открой
[вход org-b](https://craftpulse.defects.team/o/org-b/login) в отдельном окне
браузера. На переходе к GitLab сверь `client_id` с `craftpulse-org-b` в журнале
и `redirect_uri` с callback `org-b`. Войди как `cp87-admin-b` и проверь, что
интерфейс открыл `org-b`.
