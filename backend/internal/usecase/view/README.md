# Чтение задач в модуле view

`listTasks` и `getTask` рассчитывают T14, превышение целевого срока и блокировки при чтении по истории задачи и действующему сопоставлению команды. Первая страница фиксирует время `as_of` и номер среза фактов. Курсор сохраняет их вместе со значением сортировки и ID последней задачи. Отсутствующие значения сортировки идут в конце в обоих направлениях.

На каждой странице модуль заново проверяет доступ к проектам, областям источников и задачам с уровнем безопасности. В карточке видны только доступные MR, кандидаты связи и запуски текущего head. Провайдеры наблюдений получают факты уже после этих проверок. Сейчас наблюдения формирует `calc`.

Расчёт при чтении оставили после замера на 100 задачах, 1 000 событиях, 10 MR/PR и 20 запусках CI. В локальном тесте с PostgreSQL 18 p95 составил 530,3 мс для карточки и 257,9 мс для первой страницы списка. Максимум по обеим операциям составил 655,4 мс при бюджете 5 с.

Для нагрузки предусмотрен `CRAFTPULSE_LOAD=1 go test ./internal/app -run '^TestTaskViews_LoadProfileD$' -v` из каталога `backend`. Нужны Docker и `k6`. Сценарий измеряет карточку в цикле отчёта и первую страницу списка отдельной серией. В каждой серии пять сессий выполняют по пять запросов прогрева и по двадцать замеров.
