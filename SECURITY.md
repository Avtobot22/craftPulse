# Секреты и уязвимости

Не добавляйте в Git токены Git-хостинга и трекеров, API-ключи, пароли, cookies, приватные ключи и реальные `.env`. В примерах используйте пустые значения или явно вымышленные данные. Перед отправкой логов, отчётов и скриншотов удаляйте секреты и персональные данные.

При обнаружении утечки сначала отзовите или замените credential. Удаление файла новым коммитом не удаляет секрет из истории. Очистку истории согласуйте с владельцем репозитория, чтобы не потерять чужую работу.

Об уязвимости сообщайте владельцу репозитория через согласованный приватный канал. Не создавайте Issue с действующими токенами, персональными данными или подробностями, позволяющими атаковать работающий сервис. Если в GitHub доступна кнопка Report a vulnerability, используйте её.

`.gitignore` и проверки имён файлов уменьшают вероятность случайного добавления локальных данных, но не заменяют проверку содержимого diff. Автоматическое сканирование содержимого на секреты не входит в `repository-check`.
